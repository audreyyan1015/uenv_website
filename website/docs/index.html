UEnv 为 LLM 后训练提供统一的环境执行接口。当前已接入 VeRL，整体架构可以继续适配其他训练框架。

框架解耦

当前通过 Bridge 对接 VeRL，训练侧不需要了解 Worker 和环境插件的内部实现。

分布式执行

Server 统一调度，Worker Pool 主动执行 Episode，并支持环境预热与容量扩展。

可观测可靠

记录组件注册、心跳、任务状态和执行结果，便于查询问题并恢复部分运行状态。

为什么使用 UEnv

后训练系统同时面对多种训练框架、环境类型和执行资源。UEnv 把这些差异收敛到清晰的组件边界，让算法工程师与平台工程师各自关注自己的问题。

uenv-bridge

训练框架适配层

uenv-bridge 当前面向 VeRL，把 VeRL 的 rollout 样本转换为 UEnv 请求，并把执行结果转换回 VeRL 可继续训练的数据。

主要职责

接入 VeRL

在 VeRL 的 AgentLoop 阶段接收 prompt、采样参数和环境配置。

统一数据格式

把训练侧数据转换成 UEnv 的 Episode 请求，避免训练框架直接依赖 Server 和 Worker 的内部结构。

回填训练结果

把响应、奖励、轨迹和结束原因整理成 VeRL 能继续使用的结果。

一次请求如何经过 Bridge

1

接收样本

VeRL 将当前 rollout 样本交给 UEnv AgentLoop。

2

生成请求

Bridge 整理 prompt、模型地址、采样参数和环境配置。

3

调用 Adapter Core

Bridge 通过本地 gRPC 发送请求。Adapter Core 再调用进程内的 Server 模块。

4

返回 VeRL

Bridge 收到 Episode 结果后，恢复成 VeRL 需要的数据结构。

当前支持范围当前 Bridge 只维护 VeRL pre-rollout AgentLoop 路径。架构可以继续增加其他训练框架适配器，但页面不把尚未接入的框架列为现有能力。

RS

uenv-server

Episode 调度与运行状态管理

VeRL 先把训练样本交给 uenv-bridge。Bridge 将数据转换为 Episode，并通过 gRPC 发送给 Adapter Core。Adapter Core 是对外运行的服务进程，它在进程内调用 uenv-server 完成调度。uenv-server 负责控制并发、选择 Worker 或 Agent、跟踪任务状态并返回结果。

uenv-server 不是单独启动的进程uenv-server 是 Rust 库，由 uenv-adapter-core 在进程内创建和调用。对外监听 gRPC 端口的是 Adapter Core 进程。

先认识四个概念

名称含义
Episode一次完整的环境执行任务，从收到请求开始，到完成、失败、取消或超时结束。
Environment接收操作并返回观测、奖励和结束状态的程序，例如数学问答环境或代码测试环境。
Worker运行环境实例的独立进程。它向 Server 报告自己支持的环境、资源和空闲容量。
Agent执行多步工具操作的外部程序，主要用于需要修改代码、运行测试等任务。

主要职责

管理请求

识别重复请求，限制同时执行的 Episode 数量，并处理取消和超时。

选择执行资源

根据环境类型、资源、健康状态和空闲容量选择合适的 Worker；特殊任务也可以交给 Agent。

管理结果与状态

确认结果来自正确的任务分发，保存任务终态，并把结果返回 Adapter Core。

职责边界

Server 负责调度、并发控制和状态管理；Worker 或 Agent 负责实际执行；Hub 负责环境版本和制品。Server 不直接执行环境的 reset / step / close。

默认的 Native Worker 流程

Native Worker 是普通环境任务的默认路径。一次请求按下面的顺序执行：

1

接收 Episode

Adapter Core 将转换后的 Episode 请求交给 Server 模块。

2

检查并排队

Server 检查任务是否重复，并等待全局并发名额。等待超时或收到取消信号时，任务直接结束。

3

选择 Worker

Server 筛选支持该环境、资源足够、状态正常且仍有空闲容量的 Worker。

4

执行环境

Server 下发任务。Worker 准备环境实例，调用模型，执行环境步骤，并生成奖励与轨迹。

5

返回结果

Worker 单独回报最终结果。Server 完成校验和记录后，将结果返回 Adapter Core。

示例VeRL 提交一条 GSM8K 数学样本。Bridge 将样本转换为 Episode，并发送给 Adapter Core。Server 控制并发，选择可用 Worker 并下发任务。Worker 调用当前策略模型生成答案，数学环境计算奖励并记录轨迹。Worker 将结果回报 Server，Server 校验并记录后再返回 VeRL，用于后续训练。

Server 怎样选择 Worker

Server 先过滤不合格的 Worker，再在合格 Worker 之间轮流选择。

环境支持Worker 必须支持请求指定的环境类型。
资源满足CPU、内存、GPU 和环境包等条件必须满足请求。
仍有容量Worker 当前执行中的任务数不能达到容量上限。
状态正常停止接收新任务、心跳超时或状态异常的 Worker 不会被选择。

异常、超时和重试

取消或超时

任务停止继续执行，迟到的结果不会覆盖已经确定的终态。

临时通信问题

连接中断、模型服务暂时不可用或暂时没有容量时，可以按配置重试。

环境执行失败

确定性的环境失败通常直接返回，不会自动换一个 Worker 再执行一次。

高级 Agent 路径

普通任务使用 Native Worker。只有请求明确选择 Agent 模式时，Server 才会使用下面的高级路径。

路径适用任务主要执行资源
Native Worker普通问答、环境交互和评测任务Worker 与环境插件
SWE Agent需要代码仓库和隔离运行环境的软件工程任务Agent 与 Worker Runtime Gateway
Code Agent使用工具完成多步代码操作的任务ToolEnv Agent

状态是否会保存

持久化是可配置能力。启用后，Server 会保存 Episode、任务分发和最终状态，并在 Adapter Core 进程重启后恢复可恢复的信息。关闭持久化时，这些运行状态只保存在内存中，进程退出后不会保留。

RS

uenv-worker

环境执行与实例运行时

uenv-worker 连接 Server，接收已分配的 Episode，在本机准备环境实例、调用模型、执行环境步骤，并回报结果。

主要职责

报告能力

向 Server 注册支持的环境、资源、容量和网络地址，并持续发送心跳。

管理环境实例

创建、预热、复用和回收环境实例，减少重复启动带来的等待。

执行并回报

调用模型和环境插件，生成响应、奖励与轨迹，并把最终结果回报 Server。

一次任务如何执行

1

启动并注册

Worker 加载配置，启动服务，并向 Server 报告自己的能力和容量。

2

接收任务

Worker 检查任务是否有效，并确认本机仍有可用容量。

3

准备环境

优先使用本机已预热或已同步的环境实例；缺少本地可用实例时按需创建。Hub 只用于环境元数据解析或读取已预同步 EnvPackage，不是 Episode 执行热路径。

4

执行并回报

Worker 完成模型生成和环境交互，再把最终结果回报 Server。

职责边界Worker 执行 Server 已分配的任务，但不决定全局调度，也不负责维护环境版本的权威信息。
RS

uenv-hub

环境元数据与制品管理

uenv-hub 保存环境、版本、Manifest 和环境包信息，为 Worker 提供查询与下载接口。

主要职责

管理环境版本

记录环境名称、版本、接口定义和发布状态。

管理环境包

保存环境包及其校验信息，供 Worker 按需同步。

提供访问控制

支持鉴权、权限、限流和审计等管理能力。

Worker 什么时候访问 Hub

1

解析环境引用

Worker 根据请求中的环境包和版本信息查询 Hub。

2

获取 Manifest

Hub 返回环境定义、版本和需要同步的制品信息。

3

使用本地包

Worker 优先使用本地已同步或已激活的 EnvPackage；完整制品同步通常由 uenv env sync 在任务前完成。

Hub 不是每次 Episode 的必经步骤如果 Worker 已经具备所需环境和版本，就可以直接执行任务；只有需要解析或同步环境包时才访问 Hub。
职责边界Hub 管理环境元数据和制品，不参与 Worker 选择、Episode 调度和训练结果返回。
