为 LLM 后训练构建的 分布式环境执行层

UEnv 将训练框架与环境执行解耦，以统一接口连接训练集群、调度控制面、uenv-worker 与 uenv-hub，让大规模多步交互任务更易扩展、观测与复用。

一个统一执行层，连接完整后训练链路

让训练框架专注优化，让环境系统专注可靠执行。UEnv 通过标准协议屏蔽底层运行差异。

训练框架无关

通过 Bridge 适配不同训练框架，将 Episode 请求转换为统一协议，避免环境逻辑与训练代码重复耦合。

bridgeEpisodeRequest → EpisodeResult

弹性 Worker Pool

通过注册、心跳、调度与结果上报组织执行资源，支持环境实例预热和并行 Episode 执行。

插件化环境运行时

环境以独立插件进程运行，通过本地协议完成 reset、step、close 与健康检查。

全链路可观测

围绕 run、worker、environment、episode 和 step 组织状态，让异常定位与运行分析更直接。

面向大规模多步交互

控制面与执行面分离，推理服务由 Worker 直接访问，减少中心节点数据转发压力。

从训练请求到环境结果，路径清晰可控

uenv-bridge、uenv-server、uenv-worker 与 uenv-hub 连接训练请求、分布式执行和环境元数据管理。

启动 UEnv 核心服务

从仓库根目录构建 Adapter Core 与 Worker，再启动独立的 uenv-hub，并让 Worker 连接当前控制面与环境注册中心。

01 构建核心组件 02 启动 Adapter Core 03 启动 uenv-hub 04 接入 uenv-worker
查看完整快速开始 ↗
bash — uenv 
# Build core components from repository root
$ cargo build -p uenv-server -p uenv-worker -p uenv-adapter-core
$ (cd uenv-hub && cargo build)

# Terminal 1 — Adapter Core + control plane
$ UENV_ADDR=0.0.0.0:50051 \
  UENV_CONFIG_PATH=config/server.yaml \
  cargo run -p uenv-adapter-core

# Terminal 2 — environment registry
$ (cd uenv-hub && UENV_HUB_AUTH__REQUIRE_TOKEN=false cargo run -p uenv-hub-server)

# Terminal 3 — execution node, from repository root
$ UENV_SERVER_ENDPOINT=127.0.0.1:50051 \
  UENV_HUB_ENDPOINT=http://127.0.0.1:8080 \
  cargo run -p uenv-worker -- --config config/uenv-worker.yaml serve
